Salon S21 — Pending Client Change Requests

Functional specification for four additional features requested by the client after go-live training.

Project: Salon S21 Management System (desktop + mobile PWA)
Prepared by: Arnav
Audience: Tech Lead / Client sign-off
Date: 24 August 2026
Status: Proposed — not implemented
Purpose: Scope, current vs proposed behaviour, and client confirmations needed

The live product already covers bookings, billing, CRM, attendance & leave, inventory, payroll, packages (credit / membership), and master settings. The items below are new client requests and need approval before build, because they change CRM, attendance rules, package billing, inventory, and payroll.

1. Summary of requested changes

# Change Modules affected What the client gets
1 Import client customer database + long-time inactive alerts CRM, Customers, Reports Existing salon clients in S21, plus an alert for customers who have not visited for a long time
2 Per-employee late-mark buffer Attendance, Staff Master, Payroll Owner can set a different late grace (minutes) for each staff member, instead of one salon-wide 10-minute rule
3 Family amount-based package (wallet) Package Master, Billing, CRM A new package type: customer buys a rupee balance; the customer and family members can take services until that amount is used
4 Service redo / rework (no customer charge; staff product cost cut) Billing, Inventory, Payroll, Attendance/Staff Redo visit is free for the customer; products used (by ml) are deducted from the employee’s salary

2. Change 1 — Customer database import & inactive-visit CRM alert

Current system

  • CRM already stores customers (name, phone, tags, etc.) created from bookings / billing / CRM screens.
  • Excel bulk import for customers is still a prototype (not a live import pipeline).
  • There is no dedicated CRM alert list for “has not visited for a long time”.

Proposed

  1. Client shares their existing customer database (spreadsheet / export).
  2. We map and import it into S21 (name, phone, and any extra fields they provide — DOB, gender, notes, last visit if available).
  3. After import, CRM shows an Inactive / long-time no-visit alert listing customers who have not come to the salon for a defined period.

How it would work

  • Visit date is taken from the latest booking or paid invoice for that customer. If the import file already has a last-visit date, that is used until a new visit is recorded in S21.
  • CRM gets a filter or alert panel, e.g. “No visit in last X days”, with name, phone, last visit date, and days since last visit.
  • Duplicates on phone number will be merged or skipped so the same client is not created twice.
To confirm with client: (a) File format and columns they will share. (b) Inactive threshold — e.g. 30 / 45 / 60 / 90 days. (c) Should staff also see this alert on mobile, or owner/manager on desktop CRM only?

3. Change 2 — Editable late-mark buffer per employee

Current system

  • Late punch is automatic: after the staff member’s assigned shift start + 10 minutes, status becomes late.
  • This 10-minute buffer is the same for every employee (salon-wide default).
  • Late marks still feed payroll (3 lates in a month = 1 unpaid day, as already implemented).

Proposed

  • Owner can set a late buffer (minutes) on each staff profile in Staff Master (example: Employee A = 5 min, Employee B = 15 min, Employee C = 10 min).
  • Punch-in uses that employee’s own buffer against their shift start time (Asia/Kolkata).
  • If no personal value is set, the current salon default of 10 minutes continues to apply.

Where it appears

  • Settings → Staff Master: new field “Late mark buffer (minutes)”.
  • Attendance punch (desktop + mobile) uses the staff-specific value immediately on the next punch.
To confirm with client: (a) Allowed range (e.g. 0–30 minutes). (b) Who may edit it — owner only, or manager also. (c) Whether changing the buffer mid-month should affect only future punches (recommended) or past attendance too.

4. Change 3 — New family amount-based package

Current system

  • Package Master today has two types: prepaid credit bundle (N sittings / credits) and membership (% off).
  • Credits are redeemed per visit against the customer who owns the package.
  • There is no rupee-wallet package that a whole family can share.

Proposed — new package type (working name: Family Wallet / Amount Package)

  • Customer buys a package of a fixed rupee amount (example: ₹10,000).
  • That balance is stored on the package, not as sitting credits.
  • The buyer and linked family members can take services; each bill deducts the service value from the remaining balance until it reaches zero (or the validity period ends).
  • POS billing will offer this package as a payment / redemption option, same as today’s credit redeem flow, but subtracting rupees instead of 1 credit.

Family linking (proposed)

  • On the package (or customer record), owner/staff can add family members already in CRM, or create them (spouse, children, etc.).
  • Only linked members can consume the wallet. Walk-in strangers cannot.
To confirm with client: (a) Does GST apply when the wallet is purchased, when it is redeemed, or both? (b) If a service costs more than remaining balance — reject, or pay the difference in cash/UPI? (c) Max number of family members; can members be added/removed after sale? (d) Can unused balance be refunded or transferred?

5. Change 4 — Redo / rework of an unsatisfactory service

Business rule (as stated by client)

  • Customer avails a service, is not satisfied, and returns the next day or after a few days for a redo.
  • The customer is not charged again for that service.
  • Products consumed in the redo (quantity in ml / units used) are treated as cost and deducted from the salary of the employee who originally performed the service.

How it would work in S21

  1. Front desk opens the original invoice / booking and marks a Redo (linked to the original bill, customer, service, and staff).
  2. A redo visit can be booked or billed with ₹0 service charge (so GST/service total to customer is zero).
  3. Staff records products used on the redo (product + ml / qty). Inventory stock is deducted as usual.
  4. Product cost (purchase / cost price × qty used) is stored as a payroll deduction against that employee for the payroll month of the redo.
  5. On Run Payroll, net pay = existing formula minus this redo product cost.

Controls (recommended)

  • Redo allowed only within a time window (e.g. 1–7 days) — to be confirmed.
  • Owner/manager approval before salary deduction is posted.
  • Redo appears on the invoice/history so the original paid visit and the free redo stay linked.
To confirm with client: (a) Deduct from the original stylist, or the stylist who actually does the redo if different. (b) Cost basis — purchase price vs selling price of the product. (c) Maximum redo window (hours/days after original service). (d) Are service-only redos (no product) still free with no salary cut? (e) Limit of one redo per original bill, or more than one?

6. Suggested build order

Order Item Reason
1 Per-employee late buffer Small, isolated Staff Master + punch change; low risk
2 Customer import + CRM inactive alert Depends on client file; CRM-only once mapping is agreed
3 Family amount package Touches Package Master, sale, POS redemption, and family linking
4 Redo / rework + salary product cut Crosses billing, inventory, and payroll; needs the most business rules locked

7. Out of scope unless separately requested

  • WhatsApp auto-message for inactive customers (alert in CRM first; messaging can follow).
  • Changing the existing 3-lates-per-month payroll penalty formula.
  • Refunds of family wallet balance.
  • Redo of products/retail sales (this request is for salon services).

8. Sign-off

Implementation will start after confirmation of the open points in each section, especially inactive-days threshold, late-buffer editors, family-wallet GST/overspend rules, and redo window / which employee is charged.
